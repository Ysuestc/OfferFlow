# Design

## Context

小时网格 min-height=65，卡片流式扩展；默认滚至 07:00，用固定 70px 扣除头部。用户截图约显示 13–20 点，期望至少 09–20 点。

## Goals / Non-Goals

单独提升日 / 周密度；保留月视图、所有时间、原待办模型和 CRUD。

## Decisions

- 每行固定 42px，原 590px 时间窗保留，卡片两行紧凑显示并省略超长文本，完整内容可通过 tooltip / 详情查看。
- 每小时显示首项；多项显示 +N，点开独立的时段事项列表，再点击具体项进入原详情。固定高度不会裁掉无入口的事项，完整分页仍用于真实总数。
- 默认滚至 09:00，按实际 sticky 日期头高度定位，避免硬编码 70px 引起偏移。滚动仍涵盖 00–23 时。

## Change Scope / Data / API

只改日历组件与直接相关测试 / 文档；无字段、依赖、接口或事务变化，不改 App / 全局布局。测试只访问独立 calendar-review。

## Verification

以 boundingClientRect 验证两个电脑尺寸、日 / 周的 09 和 20 行完整落在时间窗内且窗口可纳入屏幕；同小时两项、101 项展开与详情、24 小时行及原新建 / 编辑 / 月视图等日历用例复核。前端构建和最终 Jar 资源核对；Java / DB 未改，不重复数据库套件。

## Risks / Rollback

紧凑卡片长标题会截断，用 tooltip / 详情保留内容；密集小时用 +N 显式展开。回退组件和规范即可，无数据回滚。

## Open Questions

无；用户明确要求改善可见时段。
